We could have claimed 44%. We claim 36%.

Some data only appears after a hole is attacked, like NVD marking it as reviewed. Using it would have lifted our catch rate from 36% to 44%, so we left it out. Rerun with new random seeds: 35% to 37% every time. Trained on shuffled answers, it catches almost nothing.

On an older year (2023), we caught 18% and the usual rule caught 23%. We report it anyway.

What is fortres?

Fortres is a triage system for security holes: a statistical model ranks all 72,670 of 2026's new vulnerabilities and picks the 500 to fix first, ranked by the warning signs known at the time, and IBM Granite models help read the descriptions and explain every pick in plain language.

  1. readGranite Embedding reads every description.
  2. rank20 models that vote, each built from 150 small decision trees.
  3. explainGranite writes each reason. Guardian checks it.

What else we found

The story has the headline results. These are the things we learned along the way.

01 67events

A few attacks come in bursts (75 holes, 67 separate events), so we count events, not holes, in our error ranges.

The 75 holes in our test came from 67 separate events, often one vendor's holes on the same day. So our error ranges count each event once, not each hole.

02 Halfthe catches, without vendor history

Attackers go back to the same vendors.

Hiding whole vendors from training cut the 2025 test's catches from 19 to 10. It's a strong clue, and a limit: a brand-new vendor gets less help.

03 6.37×EPSS jump

A popular warning score changed scale.

EPSS scores jumped 6.37 times from the July 2026 snapshot on. Fortres only compares holes scored in the same month, so the jump can't fool it.

04 249links dated after the fact

Some outside data knows the answer.

In Metasploit, 249 of 490 links to a hole were added more than 30 days after the attack code. Trusting those dates would be peeking at the answer, so we didn't.

Simpler beat clever.

We wrote the rules before seeing any results, then tried 18 ideas. We kept one: the more constrained model.

06 36%(182 of 500)

AI explanations need checking.

IBM Granite drafted a reason for each of our 500 picks, using only that hole's facts. Our own rules rejected 92 drafts, most often for using a word that isn't in the facts. IBM Granite Guardian then checked the rest against the facts and blocked 90 more. Those 182 picks show a plain fixed sentence instead. Afterwards, IBM watsonx.governance scored all 500 final reasons: on average 0.80 for staying true to the facts, and none flagged for harm or personal data.

Questions judges ask

Is fortres an LLM?
No. The ranking is 20 models that vote, each built from 150 small decision trees. IBM Granite reads the descriptions to give the ranking one clue, and writes the plain reason for each pick, which Granite Guardian checks against the facts.
Why not use an LLM to rank?
A ranking model can be tested against known outcomes, and it gives the same answer every time. A language model can make things up, so we only let it explain.
